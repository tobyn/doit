Compile doit source into a Base62-encoded behavior string.

doit compile [--release] [--stdlib stdlib_path] [-e|--error] [-j|--json] [-b behavior_id] [-l locale|--locale locale] [-o output_path] [input_path]

Reads doit source from input_path, or stdin if no path is given. If the source
contains a single behavior it is compiled into its Base62 string representation,
which is written to output_path if -o is provided, or stdout otherwise.

If the source contains multiple behaviors the `-b` option must be used to select
the compilation target by its behavior ID.

If the `-e` or `--error` option is given, any compiler warnings will be treated
as errors and compilation will fail.

If the `--release` option is given, the compiler operates in "release mode."
Currently, this means the compiler skips `assert` statements.

The `-l` or `--locale` option sets the locale used to resolve localized `@name`
blocks. If not specified, the locale is auto-detected from the operating system.
When a localized `@name` block is present, the compiler picks the best match for
the active locale, or falls back to the first entry if no match is found.

Normally, the doit CLI uses an embedded copy of the standard library. This can
be overridden with the `--stdlib` argument, which may be useful for standard
library development, or if the user wishes to use a version of the standard
library that differs from the one that ships with the compiler.

If the `-j` or `--json` option is provided, the JSON representation of the
behavior will be emitted instead of the Base62 string. This can be passed to
`doit encode` or run through the reference JavaScript encoder to create a
usable behavior string.
